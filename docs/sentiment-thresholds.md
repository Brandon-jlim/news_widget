# 뉴스 영향 분류 기준 실험

이 문서는 `호재 예상 / 악재 예상 / 영향 혼재 / 중립`의 기준을 정하기 위한 개발용 실험을 설명합니다. 판단 보류는 내부 상태 `unknown`으로만 보존하며 화면 배지를 만들지 않습니다.

**2026-11-16 적용:** 사용자 요청으로 중간 후보를 초기 운영 설정 `balanced-v1`에 반영했습니다. `tools/market_impact.py`가 제목의 수치를 직접 추출하고 `marketImpact.version=2`로 네 배지를 생성합니다. EPS는 달러 수치, 매출은 양수 예상치, 물가는 퍼센트 수치를 요구합니다. 중립은 해석되지 않은 뒷부분이 없는 비교 기사에 한정하며, 방향·중립 경계를 걸치는 전망 범위는 표시하지 않습니다. 숫자가 없는 명시적인 상회·하회는 사건 규칙을 유지합니다. 아래의 실험은 독립적인 정확도 검증이 아니며, 실제 기사 검토와 보정은 계속 필요합니다.

## 판단 기준

하나의 -1~+1 점수만으로 네 분류를 나누지 않습니다. 큰 긍정·부정 근거가 상쇄된 0과 아무 변화가 없는 0을 구분해야 합니다.

1. 사건·대상·시점과 비교 근거가 충분한지 확인합니다. 불충분하면 **미표시**입니다.
2. 개별 근거가 사건별 임계값을 넘는지 각각 판단합니다.
3. 유의미한 긍정 근거만 있으면 호재, 부정 근거만 있으면 악재입니다.
4. 유의미한 양쪽 근거가 모두 있으면 혼재입니다. 서로 빼거나 기사 내 언급 횟수를 더하지 않습니다.
5. 모두 임계값 아래이고, 비교 가능한 정보와 중립 판단 근거가 충분할 때만 중립입니다. 누락된 예상치나 파싱 실패를 중립으로 바꾸지 않습니다.

판단 대상은 명시한 종목 또는 미국 증시, 기간은 단기 예상 영향입니다. 기사 발표 후 수익률을 정답으로 사용하지 않습니다. 실제 가격 반응은 시장 전체 움직임·선반영 등의 영향을 별도로 분석해야 하는 다른 평가입니다.

## 비교할 임계값 후보

다음 값은 민감도를 비교하기 위한 **연구 가설**입니다. 중간 후보를 초기 운영 설정으로 사용하지만 문헌에서 검증된 시장 공통 기준은 아닙니다.

| 근거 | 민감 후보 | 중간 후보 | 보수 후보 |
|---|---:|---:|---:|
| EPS 예상 대비 차이 | 2% 및 $0.01/주 | 5% 및 $0.02/주 | 10% 및 $0.03/주 |
| 매출 예상 대비 차이 | 0.5% | 1% | 2% |
| 미국 CPI/PCE 예상 대비 차이 | 0.05%p | 0.10%p | 0.20%p |

- EPS는 `abs(실제−예상) >= max(abs(예상) × 상대 기준, 절대 기준)`으로 비교합니다. 예상이 0에 가깝거나 적자일 때도 비율이 폭증하거나 방향이 뒤집히지 않도록 합니다. 이 파일럿의 절대 기준은 달러 EPS에만 적용합니다.
- 매출은 실제와 예상의 통화·단위를 먼저 맞춥니다. 예상 매출이 0 이하인 경우 이 비율 실험에서 제외합니다.
- 물가는 **퍼센트포인트**로 비교합니다. 3.1%와 3.0%의 차이는 0.1%p입니다. 상승이 부정이라는 해석은 미국 주식의 금리 경로를 검토하는 가설이며 모든 시장 환경에 일반화할 수 없습니다.
- 경계값과 같은 차이는 유의미한 근거에 포함합니다. 소수점 비교는 Decimal로 처리합니다.
- 자사주 매입·파산·전망 변경 같은 비수치 사건은 별도 사건 규칙으로 둡니다. 이 실험은 해당 사건의 규모 기준을 보정하지 않습니다.
- 낮은 확실성 때문에 발생한 미표시와, 사건 자체의 작은 크기에 따른 중립은 구분합니다. 여기에는 확률·모델 confidence 점수가 없습니다.

## 2026-11-10 실험에서 확인한 것

56개 합성 경계 사례를 만들었습니다. 기대 라벨은 작성자가 정한 **초안**이며 전부 개발 데이터입니다. 일부 사례는 중간 후보의 경계 동작을 확인하도록 구성했으므로 중간 후보와의 높은 일치율은 정확도의 증거가 아닙니다.

| 가상 사례 | 당시 v1 자동 규칙 | 중간 후보에 주석 근거를 입력한 결과 |
|---|---|---|
| EPS $1.2001, 예상 $1.20 | 호재 | 중립 |
| EPS $1.20, 예상 $1.20 | 미표시 | 중립 |
| EPS 50% 상회, 매출 0.1% 하회 | 혼재 | 호재 |
| EPS·매출에 미미한 상반된 차이 | 혼재 | 중립 |
| 미국 CPI 3.01%, 예상 3.00% | 악재 | 중립 |

규칙 엔진은 텍스트를 자동 추출하지만 실험 도구의 후보 정책은 **사람이 확인할 수 있도록 구조화한 주석 근거**를 입력받습니다. 두 결과는 평가 범위가 다릅니다. 후보 결과를 자동 뉴스 분류 정확도로 해석하지 않습니다. 실행 시 `current_rules`는 그때의 운영 코드이므로 v1.9.0 이후에는 v2 결과입니다. 과거 결과 파일과 혼동하지 않도록 다른 출력 디렉터리에 보존하세요.

2026-11-10에 로컬 Benzinga·공식 발표·RSS에서 중복 ID를 제거해 기사 60개를 별도로 보존했습니다. 당시 자동 판단은 호재 3개, 혼재 1개, 미표시 56개였습니다. 이 수치는 라벨 분포이며 정확도가 아닙니다. 임계값만 조정해도 대부분의 미표시 기사가 해결된다는 근거는 없습니다. 다른 시점에 재실행하면 표본 수와 분포가 달라질 수 있습니다.

## 실행과 결과

프로젝트 루트에서 실행합니다. 유료 API·모델·번역 호출 없이 로컬 입력만 사용합니다.

```bash
python3 -m unittest discover -s tests -p 'test_impact_thresholds.py' -v
python3 tools/evaluate_impact_thresholds.py \
  --feeds data/news.benzinga.json data/news.official.json data/news.rss.json
```

`data/impact-evaluation/`에 다음 결과를 생성합니다. 기본 경로는 재실행 시 덮어쓰므로 회차를 보존하려면 `--out-dir data/impact-evaluation/run-02`처럼 별도 경로를 지정합니다. 이 디렉터리는 Git에 포함하지 않습니다.

- `results.json`: 후보 설정, 데이터셋 해시, 사례별 판단·측정값, 혼동행렬, 분류별 precision/recall, 표시율, 호재↔악재 오류 수, 근거 없는 배지 수. 예측이나 정답 표본이 없을 때 precision/recall을 100%로 채우지 않습니다.
- `review-snapshot.json`: 기사 원문 제목·소개문·대상·발행 시각과 기존 규칙 결과를 보존한 스냅샷. 정답은 비어 있습니다.
- `review.csv`: 기존 예측을 가린 검토용 표. 정답 코드·사건 그룹·대상·근거 문장·이유·검토자를 기입합니다. Excel 수식으로 해석될 수 있는 문자열은 이스케이프합니다.

검토 표의 정답 코드는 `positive`(호재), `negative`(악재), `mixed`(혼재), `neutral`(중립), `unknown`(미표시)입니다. 마지막 코드는 검토 데이터에서만 사용합니다. 기업별·관점별 답이 다르면 대상을 먼저 정해야 하며, 본문이 필요한데 제목·소개문만 있는 경우 임의로 중립 정답을 만들지 않습니다.

## 실제 기준 확정 절차

1. 현재 60개는 검토 절차를 시험하는 표본으로 사용합니다. 여러 날짜·출처·사건 유형의 실제 기사를 더 모으고, 관련 보도·재전송·수정본을 같은 `group_id`로 묶습니다. ID 중복 제거만으로 사건 중복이 모두 제거되지는 않습니다.
2. 기존 예측을 보지 않고 대상·기간·기대 분류·근거를 검토합니다. 가능한 경우 두 검토자의 불일치를 조정합니다. 합성 사례와 실제 검토 사례의 성과를 섞지 않습니다.
3. 검토 결과를 fixture 형식으로 옮기고 `label_status=reviewed`로 바꿉니다. `annotation`에는 실제·예상 수치와 원문 근거, 정보 충분 여부를 기록합니다. CSV 자동 수입과 자동 근거 추출은 아직 제공하지 않습니다.
4. 개발·조정용(validation)·최종 확인용(test) 데이터를 사건 그룹과 시간으로 분리합니다. 도구는 같은 사건 그룹이 여러 분할에 존재하면 오류를 냅니다. 개발 가설을 만드는 데 사용한 표본을 독립 테스트로 재명명하지 않습니다.
5. 조정용 표본에서 **분류별 표시 정밀도와 표시율의 관계**를 비교합니다. 초기 검토 목표로 호재·악재 각각 precision 90% 이상, 반대 방향 오분류 최소화를 제안합니다. 이는 제품 목표 가설이며 이번 결과로 충족을 검증하지 않았습니다. 중립·혼재도 각각 확인하고 분류별 표본 수와 불확실성을 함께 보고합니다. 몇 건을 맞힌 100%로 기준을 확정하지 않습니다.
6. 후보를 하나 고정한 후 더 늦은 날짜의 테스트를 한 번 확인합니다. 자동 추출까지 포함한 결과를 평가해야 실제 위젯에 적용할 수 있습니다. 최종 테스트 결과를 보고 다시 조정했다면 새 독립 테스트 표본이 필요합니다.

검토 데이터를 준비한 다음의 실행 예:

```bash
python3 tools/evaluate_impact_thresholds.py --cases path/to/reviewed.json --split validation
python3 tools/evaluate_impact_thresholds.py --cases path/to/reviewed.json --split test --policy balanced
```

두 번째 명령의 `balanced`는 형식 예시이며 선정 결과가 아닙니다. 최종 테스트는 미리 정한 후보 하나를 명시해야 실행됩니다.

임계값은 목적에 맞는 평가 지표로 조정하며, 같은 데이터로 조정과 검증을 반복하면 과적합될 수 있습니다. 참고: [scikit-learn의 decision threshold 설명](https://scikit-learn.org/stable/modules/classification_threshold.html). 모델의 숫자를 확률로 표시하려면 별도 보정 검증이 필요합니다. 참고: [probability calibration 설명](https://scikit-learn.org/stable/modules/calibration.html).
